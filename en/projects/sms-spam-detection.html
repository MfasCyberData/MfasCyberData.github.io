How do you filter unwanted SMS without blocking real messages?

01 / Context & question

A spam filter can fail in two ways, and they do not cost the same.

Every incoming SMS must be classified as ham (a legitimate message) or spam (promotions, fake prizes, premium-rate numbers).

A filter can let a spam through: annoying. It can also block a real message, such as an appointment or a login code: much worse for the user. Everything that follows is therefore built to measure these two errors separately, not just an overall percentage of correct answers.

The project question

On this set of messages, does a model that follows word order really beat a much simpler classic method?

Before choosing a model, I first needed to know what these messages look like.

02 / Exploratory data analysis (EDA)

Exploration reveals three things that shape everything after: imbalance, duplicates and a recognisable spam style.

Exploratory data analysis (EDA) means looking at the data before modelling: how many messages, what share of spam, which anomalies, which visible differences between the two classes. It is what drives the right preparation and evaluation choices.

What I checked
  1. counted messages per class and looked for missing values;
  2. looked for duplicated messages;
  3. compared the length of ham and spam messages;
  4. listed the most frequent words in each class.

What these findings change

The imbalance means tracking spam precision and recall rather than accuracy. Duplicates must be removed before splitting, otherwise the same message could be learned and then “recognised” at test time. Links and sales vocabulary show that cleaning must not erase these clues.

These observations directly guided how the text was prepared.

03 / Text preparation

Deliberately light cleaning, to keep the clues the filter needs.

Transformations applied to every SMS
  1. lowercase (“FREE” and “free” become the same word);
  2. each link replaced by the word urltoken: the exact address changes from one spam to another, but the presence of a link is a signal;
  3. punctuation and repeated spaces removed;
  4. labels encoded: ham = 0, spam = 1.

I did not remove short words or numbers: in SMS, “txt”, “150p” or a short code are precisely typical of spam, as the exploration showed.

Once the messages were prepared, the evaluation had to be organised before training anything.

04 / Training, validation and test split

Three separate sets of messages, each with a precise role.

Training · 3,609models learn
Validation · 774tuning and threshold
Test · 774final evaluation, once

Key terms in this step

Validation set
Here, 774 messages set aside during training. I use them to stop the BiLSTM’s training at the right time and to choose the decision threshold. The model never learns from them.
Test set
774 other messages, never used for any choice. They give the final result, as new SMS would.
Stratified split
Each set keeps the same spam share (12%), so the three are comparable.

The BiLSTM vocabulary and the TF-IDF weights are learned only from the 3,609 training messages. Otherwise, words seen only in the test set would influence the model, and the result would be too optimistic.

With this frame in place, I could train two very different approaches under the same conditions.

05 / Two models, two ways of reading an SMS

A model that follows word order, against a method that weighs important words.

Key terms in this step

TF-IDF
Gives each word (and word pair) a weight: high if it is frequent in this SMS but rare across all messages. “claim” or “prize” weigh a lot; “the” almost nothing.
Logistic Regression
Combines these weights into a spam probability. Simple, fast and readable: the baseline to beat.
Embedding
Turns each word into a small vector learned during training, so that words used in similar ways (“win”, “prize”) get similar vectors.
BiLSTM
A neural network that reads the message word by word, in both directions. It can take order into account: “call now to claim” does not mean the same as the same words shuffled.
How I trained the BiLSTM
  1. each SMS is brought to 33 words, the length of 95% of training messages (shorter ones padded, longer ones cut);
  2. class weights give more importance to errors on spam, the minority class;
  3. training stops when the validation error stops decreasing (early stopping), before the model memorises the training set.

Both models output a probability; what remained was deciding when a message is declared spam.

06 / Choosing the decision threshold

The threshold sets the trade-off between spam let through and real messages blocked.

Key terms in this step

Decision threshold
The probability from which an SMS is classified as spam. 0.50 by default; higher, the filter blocks fewer real messages but lets more spam through.
Precision (spam)
Among blocked messages, the share that are really spam.
Recall (spam)
Among real spam, the share the filter stops.
F1 (spam)
A balanced average of precision and recall: it can only be good if both are.

I tested thresholds on the validation set and kept the one with the best spam F1: 0.83 for the BiLSTM and 0.56 for TF-IDF + Logistic Regression. The BiLSTM’s high threshold suggests very clear-cut probabilities on obvious spam: it can demand strong certainty before blocking.

Fixed before the test.

Both thresholds were frozen before any evaluation on the test set, so the final result is not tuned on the messages used to measure it.

With models and thresholds fixed, the test set could finally be used.

08 / Interpretation & real-world value

The best score does not always mean the best production choice.

The BiLSTM blocks two fewer real messages and stops one more spam: it is the best classifier in this experiment. But TF-IDF stays very close, and even gets slightly higher areas under the ROC and precision-recall curves, meaning it ranks messages just as well when the threshold varies.

In practiceChoose according to context

The BiLSTM if every blocked real message matters; TF-IDF if speed, easy updates and explainability come first, since the words driving each decision can be read directly.

What the errors showRecall is the point to improve

With 13 errors out of 774 messages, the BiLSTM is rarely wrong. But 9 of the 96 spam still get through, almost one in ten: that is where more recent data or a richer model would help most.

It remains to be clear about what this experiment proves, and what it does not.

Decision: the BiLSTM is the best tested classifier, but the gap is small enough that TF-IDF + Logistic Regression remains a credible choice when simplicity, speed and explainability matter more.

09 / Limits & lessons

A solid result on this set of messages, to be confirmed on recent SMS.

  • An old, English-only set of messages (corpus): spam vocabulary has changed since.
  • Training and test come from the same source: no validation on another dataset.
  • No speed or memory measurement, which would matter for deployment.
What I learned

Comparing a complex model with a simple method, on the same split and with a threshold chosen on validation, teaches more than an isolated score. Here the BiLSTM wins, but the small gap shows that extra complexity is only worthwhile when the gain justifies the operational cost.

Going further

I would extend the study by testing a recent SMS dataset, trying a transformer-type model and setting the threshold from the real cost of each error. The notebook details every step and its outputs.
